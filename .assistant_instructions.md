# Instrucciones de Genie Code para Andes Bank

Estás ayudando a construir el lakehouse de **Andes Bank**, un banco argentino ficticio (BCRA). Reglas del proyecto:

- **Catálogo** `andes_bank`. Capas: `sim` (sistemas origen simulados: NO usar desde el lakehouse), `landing` (Volume),
  `bronze`, `silver`, `gold`, `semantic`, `ops`.
- **El código vive en el paquete `andes_bank`** (`src/`), testeado con pytest. Los notebooks son delgados: llaman al
  paquete. No pongas lógica de negocio en un notebook.
- **Bronze** guarda lo que llegó tal cual (texto o JSON crudo) con linaje (`_source_file`, `_delivery_date`,
  `_ingested_at`). Nunca limpiar en bronze.
- **Silver**: una función por problema del catálogo (`docs/03_catalogo_de_problemas.md`), con su ID en un comentario
  (DAT-02, API-06...). Expresiones de Spark, sin UDFs de Python. Filas inválidas a `silver.quarantine` con motivo.
- **Escrituras idempotentes**: MERGE insert-only para hechos, `utils.delta.replace_where` para reemplazar un rango.
  Nunca `saveAsTable` + `replaceWhere` (bitácora R09).
- **Nombres**: tablas y columnas de silver/gold en castellano, snake_case. Montos con `decimal(18,2)`; siempre también
  `importe_ars` e `importe_usd` (al oficial de `gold.dim_fecha`).
- **Horas**: `*_utc` en UTC; `*_local` en hora argentina (America/Argentina/Buenos_Aires, sin horario de verano).
- **Secretos**: sólo `dbutils.secrets.get("andes_bank", ...)`. Nunca un token, SAS o contraseña en el código.
- **APIs**: usar `andes_bank.ingestion.api_client.ApiClient` (reintentos, backoff, token, conciliación). No llamar a
  `requests` a mano.
- **Funciones para Genie**: parámetros de fecha como STRING 'yyyy-MM-dd' (con DATE, Genie rechaza el agent).
